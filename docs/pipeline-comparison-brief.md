# Choose a low-level G1 tracking pipeline for a slower trajectory planner

## Decision and deliverables

Determine when to use SuperMimic or wbc-mjlab, and with which configuration, for a 50 Hz Unitree G1 controller following previously unseen, general-purpose whole-body motions from a slower planner. Deliver a Markdown report with playable comparison videos, data tables and reproducible commands. Give separate answers for **which existing checkpoint to use today** and **which pipeline to use for future training**. Carry the work through evaluation, matched training, analysis, and the final report.

The robot has joint encoders and an IMU. Past actions, causal history and signals derived onboard from those inputs are available. The high-level controller supplies the commanded trajectory. External motion capture and perfect simulated robot pose, translation, heading, or base velocity are unavailable to the actor. Simulator truth is available to the evaluator. Both reliable completion and faithful path and pose tracking matter. The planner interface and tracking tolerances are open design questions. Nominal simulation is the primary evaluation. Describe any remaining barriers to hardware use.

## Experiment

1. **Audit the controllers and reproduce native results before comparing them.** Inventory checkpoints, training clips, action conventions and every actor input, including quantities inside the reference encoder. Check SuperMimic’s use of the current pelvis orientation when expressing future goals. Check the WBC SE variants’ anchor error and base velocity, and the EE variants’ command/action interfaces. Show how each eligible input can be produced causally on the robot. Keep privileged configurations as labeled diagnostic upper bounds. Do not silently drop an input, substitute zeros or feed simulator truth to make a checkpoint run.
2. **Establish shared motions and physics.** Assemble representative locomotion, turns/transitions, floor motions/get-ups, coordinated upper-body skills and dynamic/jumping motions. Record provenance, sampling rates and family counts. For existing weights, verify that anything called unseen is outside both training libraries, grouping mirrors, overlapping segments and near-duplicate performances. Label uncertain membership. For new training, use matched train/validation/test manifests split by source performance or sequence before augmentation. Reserve the final test for the frozen comparison. Separate native-reproduction clips, validation clips used for development, and independent test clips.
3. **Validate a common test environment.** Use the same robot, realistic actuator limits, control period, contacts, initial states, reference clock, trial endings and scoring. Preserve each policy’s intended joint ordering, offsets, gains, action decoding and observation history through documented adapters. Check adapter outputs against native actions on recorded observations, then inspect short closed-loop replays. Isolate consequential physics or interface mismatches with paired controls and disclose residual differences. Never equate native training reward across these pipelines.
4. **Evaluate existing checkpoints first.** Screen all six corrected WBC variants for eligibility and compare the eligible ones with the accepted SuperMimic policy. Select promising candidates on validation data. Report data-exposure and deployment-input differences. If a frozen controller needs unsupported inputs or more preview than the planner provides, measure that limitation and consider a retrained variant.
5. **Test the two-rate interface.** Keep the low-level step at 20 ms. Vary planner update rate and published preview duration independently. A useful initial grid is 2, 5 and 10 Hz with short, medium and approximately 0.9 s preview; narrow it on validation evidence. Only expose targets already published by the planner. Document interpolation, end padding and behavior when a plan is revised. Include smooth continuation, feasible speed or direction changes and transitions mid-motion. Derive revisions consistently across policies; use real planner logs if available and label synthetic tests. Full prerecorded preview can serve as an upper bound. Recommend the smallest adequate preview, update rate and reference fields.
6. **Train matched candidates, then compare cost and attainable quality.** Train at least one sensor-compatible candidate from each pipeline from scratch on the shared corpus. Keep the observation budget, planner information, hardware class, validation access and evaluation conditions comparable. Preserve meaningful algorithmic differences. Use multiple independent training seeds for finalists and paired evaluation trials. Compare checkpoints at equal GPU-hours and after validation performance levels off. Report tuning effort, stability, throughput and training cost. Do not equate PPO iterations with SuperMimic collection iterations.
7. **Choose practical tolerances on validation motions.** Inspect synchronized reference overlays covering acceptable execution, noticeable but harmless deviations, sustained drift, wrong poses and falls. Establish **deliberately forgiving**, common limits for horizontal root-path error, heading error and root-relative whole-body pose error. Explain the limits in meters/degrees, their aggregation and the duration allowed for brief excursions. Freeze them, the failure rules, and the checkpoint-selection rule before scoring the final test. A successful trial must finish and track acceptably. Rank by success averaged equally across motion families. Also report completion alone, raw error distributions, unconditional coverage, uncertainty across motions/seeds, and sensitivity to looser and tighter limits. An early fall must not improve the primary score by shortening the measured trajectory. Include action smoothness, saturation and inference latency versus the 20 ms deadline where they inform the choice.
